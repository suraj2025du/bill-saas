# Fix Log - Batch 13 (GSTR-1 files)

Completed on 2026-11-08. Resolves CO 09 (JSON blanks), CO 13 (JSON version & hash), and verifies CO 10 (CSV columns alignment).

## CO 09: Empty/blank string values in GSTR-1 JSON
- **What was wrong:** Empty strings (such as `hsn_sc: ""` or `desc: ""` for items without specific descriptions or HSNs) were serialized in the final portal JSON, which would cause schema validation failures during offline tool or portal imports.
- **Root cause:** The GSTR-1 JSON generator did not strip empty, null, or undefined fields prior to output.
- **Fix:** Implemented a robust recursive `stripEmpty` helper inside `src/core/gst/returns/gstr1.ts` that removes any key containing empty strings (`""`), `null`, or `undefined` values from any nested object or array before outputting the final JSON.

## CO 13: GSTR-1 JSON version ("GST3.0.4") & hash headers
- **What was wrong:** The GSTR-1 JSON output explicitly added outdated version headers (`GST3.0.4`) and a dummy `hash: "hash"` property, which does not match modern portal-proven generators (like India Compliance, which omits version/hash or uses the updated `GST3.2.4` structure).
- **Root cause:** Hardcoded headers in `gstr1Json` initialization.
- **Fix:** Removed hardcoded `version` and `hash` fields from `gstr1Json` initialization to match portal-proven structures where only `gstin` and `fp` are written as core keys.

## CO 10: GSTR-1 CSV Column sets & alignment
- **Verification:** Verified that `src/core/gst/returns/gstr1Csv.ts` generates UTF-8 with BOM CSV exports that are perfectly aligned with official offline tool template columns (`GSTIN/UIN of Recipient`, `Receiver Name`, `Invoice Number`, etc.) and include necessary tax columns for audit verification.
